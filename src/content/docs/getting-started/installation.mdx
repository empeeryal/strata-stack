## Prerequisites

- **Node.js 24.x.** The repository pins the version in `.nvmrc`, and the `engines` field in
  `package.json` tells Vercel and Netlify which runtime to use.
- **pnpm 12.** Pinned through the `packageManager` field; run `corepack enable` if pnpm is not
  installed. pnpm's own settings (allowed build scripts, overrides, audit exceptions) live in
  `pnpm-workspace.yaml`.
- **Git.** Husky installs a pre-commit hook that runs lint-staged.

## Create the project

Start from a copy of the template rather than a fork, so your repository has its own history and
is not listed as a fork of Strata. Pick one:

- **Use this template.** The
  [Use this template](https://github.com/new?template_name=strata-stack&template_owner=empeeryal)
  button on GitHub creates a repository under your account with a single initial commit. Clone it
  as usual.
- **Astro's CLI.** `pnpm create astro@latest my-site --template empeeryal/strata-stack` downloads
  the code into `my-site`, offers to install dependencies and initialises a Git repository.
- **Clone.** `git clone https://github.com/empeeryal/strata-stack.git my-site` keeps Strata's full
  history, which lets you merge later template changes with Git. Rename the `origin` remote to
  `template` before adding your own.

## First run

<Steps>

1. Install dependencies inside the project folder.

   ```bash
   cd my-site
   pnpm install
   ```

2. Create your environment file. The defaults work for local development without any external
   service.

   ```bash
   cp .env.example .env
   ```

3. Create the local SQLite database and apply the migrations.

   ```bash
   pnpm db:migrate
   ```

4. Start the development server at `http://localhost:4321`.

   ```bash
   pnpm dev
   ```

</Steps>

<Callout type="note">
  Search uses a static index that is generated during `pnpm build`. Run a build once if you want to
  try the search dialog in development.
</Callout>

## Rename checklist

Everything that identifies the site lives in a few files. Work through this list once when you
start a new project:

1. `src/site.config.ts`: name, tagline, description, canonical URL, author, repository, social
   links, navigation and footer links.
2. `package.json`: the `name`, `description` and `version` fields. `wrangler.jsonc`: the Worker
   `name` (Cloudflare only).
3. `public/favicon.svg`: replace the mark, then run `node scripts/generate-icons.ts` to regenerate
   the PNG icons. Update the mark in `src/components/site/Logo.astro` and `src/lib/og-template.tsx`
   too.
4. `src/styles/global.css`: the primary and accent hues in both colour sets, and `themeColor` in
   the site config so the browser UI matches.
5. `src/content/authors/*.json`: your author profile.
6. `LICENSE`, `SECURITY.md`, `public/.well-known/security.txt` and `src/content/legal/*`: legal
   text and contact details.
7. `CHANGELOG.md`: start your own release history.
8. `.github/CODEOWNERS`: your GitHub handle. `README.md`: the CI badge and the deploy buttons
   point at this repository; the Vercel button also lists the environment variables it asks for.
   `.github/ISSUE_TEMPLATE/config.yml`: the security advisory link.
9. `src/content/blog/*` and `src/content/docs/*` are Strata's own posts and documentation. Delete
   or replace them, and remove the matching redirect for the old announcement slug from
   `astro.config.ts`.

## Verifying the setup

Run the complete quality suite before your first commit:

```bash
pnpm check        # astro check (TypeScript + Astro diagnostics)
pnpm lint         # ESLint
pnpm format:check # Prettier
pnpm test         # Vitest unit and component tests
pnpm build        # production build for the Node target
pnpm test:e2e     # Playwright end-to-end tests against the build
```

Every one of these commands also runs in CI on each pull request.
